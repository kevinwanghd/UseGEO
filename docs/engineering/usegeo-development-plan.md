# usegeo.blog MVP 开发执行计划

## 1. 文档信息

- 项目名称：`usegeo.blog`
- 文档类型：`Development Plan`
- 适用阶段：`MVP`
- 当前版本：`v1.0`
- 文档状态：`执行版`

## 2. 开发目标

在 `1-2 周` 内完成一个可上线、可收集线索、可验证转化闭环的 MVP 版本。

本阶段开发重点不是做“完整平台”，而是做一个：

- 看起来专业
- 用起来顺畅
- 能收集有效 Lead
- 便于快速迭代

的产品型站点。

## 3. 交付范围

本阶段交付以下内容：

- 首页 Landing Page
- 品牌 AI 曝光度诊断器
- AIGC 营销内容 ROI 试算器
- 文章列表 / 文章详情页基础模板
- 留资表单
- Footer 合规页入口
- 基础埋点位

## 4. 技术方案

### 4.1 基础结构

- 内容与页面管理：`WordPress`
- 工具模块：`HTML / CSS / JS`
- 嵌入方式：
  - 首页 Hero 工具使用自定义 HTML 模块
  - 文章侧边栏工具优先使用可复用代码块或 shortcode

### 4.2 推荐实现原则

- 工具逻辑与页面样式尽量解耦
- 首页工具和文章页工具共用一套样式变量
- 所有 MVP 逻辑尽量前端可运行，不依赖复杂后端

## 5. 页面拆分

## 5.1 首页

模块拆分建议：

1. 顶部导航
2. Hero 区
3. 品牌 AI 曝光度诊断器
4. Value Proposition 区
5. Content Hub 区
6. Footer

### 首页重点

- 首屏必须先完成
- Hero 和诊断器是第一优先级
- Content Hub 只做支持性展示，不抢主 CTA

## 5.2 文章详情页

模块拆分建议：

1. 文章主阅读区
2. Sticky Sidebar
3. 推荐阅读
4. Footer

### 文章页重点

- 优先保证可读性
- 侧边栏 CTA 要稳定可复用
- 移动端转为文末 CTA 模块

## 6. 组件拆分

## 6.1 品牌 AI 曝光度诊断器

建议拆成以下子模块：

- 输入区
- 加载态区
- 结果评分卡
- 雷达图区
- 结果解读区
- 留资解锁区

## 6.2 ROI 试算器

建议拆成以下子模块：

- 输入控件区
- 图表区
- 关键指标区
- CTA 区

## 6.3 通用组件

建议沉淀一套通用 UI 组件：

- 按钮
- 输入框
- 卡片
- 区块标题
- 表单字段
- CTA 模块

## 7. 前端实现建议

### 7.1 样式

- 使用 CSS 变量统一颜色、圆角、边框、间距
- 保持首页和文章页视觉一致
- 优先保证桌面和移动双端都可用

### 7.2 图表

- MVP 不需要复杂图表库
- 可优先使用轻量方案实现柱状图和雷达图
- 如果时间紧张，雷达图可先用简化实现

### 7.3 加载态

- 诊断器必须有骨架屏和动态文案
- 加载时长建议固定在 `2-3 秒`
- 动画不要复杂，但要有真实感

## 8. WordPress 集成建议

### 8.1 内容页

- 首页由 WordPress 页面承载
- 文章页使用主题模板
- 合规页使用普通静态页面

### 8.2 工具模块

推荐两种方式：

#### 方式 A：自定义 HTML 模块

适合：

- 首页主工具
- 结构稳定、更新频率不高的模块

#### 方式 B：Shortcode 插件

适合：

- 文章页复用的工具模块
- 未来需要在多个页面复用的 CTA 区

建议：

- MVP 可先用 HTML 模块快速落地
- 稳定后再抽 shortcode

## 9. 埋点与验证

MVP 最低埋点要求：

- 首页访问
- Hero 工具启动
- 诊断完成
- 留资表单曝光
- 留资表单提交成功
- ROI 工具使用
- 文章页 CTA 点击

验证目标：

- 确认主漏斗能跑通
- 确认转化点是否有效
- 为下一轮优化提供依据

## 10. 建议开发顺序

### 阶段 1：先打通主漏斗

1. 首页骨架
2. Hero 区
3. 品牌 AI 曝光度诊断器
4. 留资表单

目标：

- 用户能从首页完成一次完整诊断并提交表单

### 阶段 2：补足信任与辅助转化

1. Value Proposition 区
2. Content Hub 区
3. ROI 试算器
4. Footer 合规信息

目标：

- 提升站点完整度和 B2B 可信度

### 阶段 3：补文章页和埋点

1. 文章详情页模板
2. Sticky Sidebar CTA
3. 埋点与基本验证

目标：

- 打通内容入口到工具入口的辅助路径

## 11. 1-2 周建议排期

### Day 1-2

- 搭首页结构
- 确定样式变量
- 实现 Hero 与基础导航

### Day 3-4

- 完成品牌 AI 曝光度诊断器
- 加入加载态和结果态
- 接入留资表单

### Day 5-6

- 完成 Value Proposition 和 Content Hub
- 完成 ROI 试算器
- 完成 Footer 和合规页入口

### Day 7-8

- 完成文章详情页模板
- 接入 Sticky Sidebar CTA
- 补移动端适配

### Day 9-10

- 补埋点
- 自测与修正
- 准备上线

## 12. 验收标准

产品与开发联合验收至少确认：

1. 首页是否具备强首屏和清晰 CTA。
2. 主工具是否能完整跑通输入、加载、结果、留资。
3. ROI 工具是否稳定可用。
4. 移动端是否可正常使用。
5. 页面是否整体更像 SaaS 产品，而不是博客站。
6. 埋点是否足够支持首轮验证。

## 13. 风险与取舍

### 风险 1：设计做得太多，影响上线速度

取舍：

- 优先首屏和主工具
- 次级模块可以简化

### 风险 2：图表实现复杂度过高

取舍：

- 优先保证结果清晰
- 不追求高保真复杂可视化

### 风险 3：WordPress 嵌入方式不稳定

取舍：

- 先用最直接可控的 HTML 模块
- 后续再组件化

## 14. 当前阶段建议

如果资源有限，只盯三件事：

1. Hero 是否强
2. 主诊断工具是否可信
3. 留资表单是否顺滑

这三件事决定 MVP 是否值得继续放量。
