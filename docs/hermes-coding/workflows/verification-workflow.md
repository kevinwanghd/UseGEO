# Verification Workflow

## 目的
定义 UseGEO 项目中任务完成前必须如何验证。

---

## 总原则

1. **未验证前，不宣称完成**
2. **验证优先检查主转化路径**
3. **验证优先覆盖真实运行时代码**
4. **先验证任务直接影响面，再验证关键相邻路径**
5. **如果验证失败，先回到根因分析，不直接继续打补丁**

---

## UseGEO 项目验证优先级

### P0：主转化路径
必须优先验证：
- 首页能正常打开
- Hero 正常显示
- Scanner 正常交互
- 留资表单能提交
- success / invalid / failed 状态路径正常
- 文章页 CTA 不被破坏

### P1：页面和交互完整性
- 模板是否正常渲染
- 样式是否明显错乱
- 脚本是否正常加载
- 桌面端是否可用
- 移动端是否可用

---

## 默认验证顺序
1. 静态确认：改动文件、目录、路径是否正确
2. 资源加载确认：enqueue、DOM、样式脚本是否匹配
3. 直接影响面验证
4. 关键相邻路径验证
5. 主转化路径验证
6. 桌面 / 移动验证

---

## 验证失败时的处理方式
1. 说明失败发生在哪一步
2. 判断失败类型
3. 回到根因分析
4. 做最小修正
5. 重新验证

---

## 完成判定标准
只有同时满足以下条件，才可以宣称任务完成：
- 改动发生在正确运行时目录
- 本次任务直接影响面已验证
- 关键相邻路径已做最小必要验证
- 如触达主转化路径，则主路径已验证
- 输出中包含明确验证依据
